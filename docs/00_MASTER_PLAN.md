v2 사용자(시형 님)로부터 받은 피드백 10가지와 신규 기능 1개(저장/불러오기)를

## 작업 원칙 (Claude Code가 반드시 지킬 것)

### 1. 작업 단위마다 WORK_LOG.md 갱신

각 작업(A-1, A-2, ..., B-1, ...) 완료 시점에 `WORK_LOG.md` 끝에 항목 추가:

```markdown
## [YYYY-MM-DD HH:MM] A-N. 작업 제목
- 수정 파일: index.html, extract_data.py
- 핵심 변경: (2~3줄 요약)
- 검증 결과: (어떻게 확인했는지)
- 사용자 확인 필요 사항: (있다면)
```

이렇게 누적하면 세션이 끊겨도 다음 세션에서 이어갈 수 있다.

### 2. 사용자 확인 지점에서 멈춘다

작업 문서에 **"⏸ 사용자 확인 필요"** 마커가 있으면 그 작업을 마치고 다음 작업으로
넘어가지 말고, 사용자에게 명확히 보고하고 응답을 기다린다.

예: "A-1 시트 분석 완료. 결과는 다음과 같습니다 [...]. 이 시트명으로 A-2를
진행해도 될까요?"

### 3. 자체 검증 후 보고

각 작업 끝에 "검증" 절이 있다. Claude Code가 직접 다음을 수행:
- 코드 수정 후 문법 검사 (Python은 `python3 -m py_compile`, JS는 `node --check` 또는
  브라우저 콘솔 시뮬)
- 데이터 변경 시 샘플 학교 1~2개로 결과 확인
- 검증 결과를 WORK_LOG.md에 기록

### 4. 커밋·푸시는 사용자 승인 후

각 Phase 마지막 단계에 커밋·푸시 작업이 있다. **사용자에게 변경 사항 요약을 보여주고
승인받은 뒤** 실행한다. 단독 판단으로 푸시하지 않는다.

### 5. 로컬 서버 테스트 안내

UI 관련 변경 후에는 사용자에게 로컬 테스트 방법을 안내:

```
python3 -m http.server 8080
→ http://localhost:8080
```

배포 전 사용자가 직접 확인할 시간을 보장한다.

### 6. 문서·코드 동기화

코드를 수정하면 관련 문서(`README.md`, `CLAUDE.md`)도 함께 갱신한다.
"v2 → v3 변경 사항"이 문서에서 누락되면 안 된다.

## 피드백 분류 및 우선순위

| # | 피드백 | 처리 Phase |
|---|---|---|
| ① | 중복이수 방지 (충남외고 인문어문 → 문학 4학기 중복) | A |
| ② | 학급수 표시 삭제 (현행화 안 됨) | B |
| ③ | 순증 (6) 형태 활성화 | A |
| ④ | 교과군별 필수 이수학점 충족 표시 | B |
| ⑤ | 창체 데이터 통합 (192학점 정상 표시) | A |
| ⑥ | "프리셋" → "추천 과목" 용어 변경 | B |
| ⑦ | 과학(군) / 정보과학 분리 | A |
| ⑧ | 평가 처리 유형 표시 | A |
| ⑨ | 학교 통합 검색 (지역+검색 통합) | B |
| ⑩ | 학과별 선택과목 안내 별도 사이트 | **C (이번 작업 범위 아님)** |
| ★ | **시뮬레이션 결과 저장/불러오기 (Excel/PDF/JSON)** | B |

### 분류 기준

- **Phase A**: 데이터 추출 스크립트(`extract_data.py`) + 백엔드 로직 수정 위주.
  먼저 처리해야 Phase B의 UI 변경이 의미를 가짐.
- **Phase B**: 프론트엔드(`index.html`) UI·UX 개선 + 신기능 추가.
- **Phase C**: 학과별 선택과목 안내는 **본 사이트에 통합하지 않는다**.
  데이터 단위(고교 vs 대학)와 사용 시점이 달라 정보 구조가 흐려진다.
  별도 프로젝트(`dept_course_guide` 저장소)로 추후 진행.
  이번 작업에서는 Phase B 헤더에 "학과별 선택과목 안내 →" 외부 링크 슬롯만
  마련해둔다 (URL은 일단 placeholder).

## 작업 진행 순서

```
START
  ↓
[Phase A 시작]
  → 01_PHASE_A_TASKS.md 따라 A-0 ~ A-8 진행
  ↓
[Phase A 자가 테스트] ⏸ 사용자 확인 필요
  → 사용자가 배포 사이트에서 체크리스트 검증
  ↓
[Phase B 시작]
  → 02_PHASE_B_TASKS.md 따라 B-1 ~ B-6 진행
  ↓
[Phase B 자가 테스트] ⏸ 사용자 확인 필요
  ↓
END (v3 배포 완료)
```
