## A-1. xlsx 추가 시트 구조 파악

목적: 창체·평가유형 데이터가 어느 시트에 있는지 정확한 시트명·컬럼명을 확인.

수행할 작업:

1. 일회용 분석 스크립트를 작성하여 `2026학년도_*.xlsx`의 모든 시트를 조사:
   - 시트 이름 목록
   - 각 시트의 shape (행×열)
   - 첫 5행 미리보기 (NaN은 빈칸 처리)
2. 결과를 사람이 읽기 좋게 출력. 특히 시트명에 "창체", "창의", "체험", "평가",
   "성취", "evaluation" 등이 포함된 시트는 별도로 강조.
3. 발견한 시트 중 다음 후보를 식별:
   - **창체 시트 후보**: 학교코드 + 6학기 학점 또는 학년별 학점이 들어있을 가능성
   - **평가유형 시트 후보**: 학교코드 + 과목명 + 평가 처리 유형이 들어있을 가능성
4. 분석 결과를 정리해서 사용자에게 보고.

⏸ **사용자 확인 필요**: 분석 결과 보고 후, 다음 중 하나의 답을 받는다:
- (a) "창체 시트는 X, 평가 시트는 Y로 진행" → A-2로
- (b) "원본 xlsx에 해당 시트 없음. 시형 님이 새 버전 받아 추가 업로드 후 다시"
  → 작업 일시 중단

WORK_LOG.md 기록: 어떤 시트가 발견됐고 어떻게 처리할지 결정 사항 기록.

## A-2. 창체 데이터 통합 (extract_data.py 수정)

목적: 학교별 창의적 체험활동 학점 6학기치를 추출해서 편제 JSON에 통합.
이는 우측 패널 총 학점이 192로 정상 표시되기 위한 전제다.

수행할 작업:

1. `extract_data.py`에 창체 시트(A-1에서 확정한 시트명) 읽기 로직 추가.
2. 학교코드별 6학기 창체 학점 매핑 생성. 다음 케이스를 모두 처리:
   - 소수점 학점 (예: 1-1=3.5, 1-2=3.5)
   - 학년별 차이 (예: 1학년 7학점/학기, 3학년 5학점/학기)
   - 학교마다 다른 패턴
3. 각 학교의 편제 JSON 최상위에 다음 필드 추가:
   ```json
   "changche": {
     "semesters": [1-1, 1-2, 2-1, 2-2, 3-1, 3-2],
     "total": 합계
   }
   ```
   기존 데이터에 `changche` 키가 이미 있다면 (v2 데이터 구조 확인 필요)
   기존 키를 덮어쓰거나 호환되게 확장.
4. `python3 extract_data.py` 실행.

검증 단계:

1. 다음 학교 샘플의 창체 학점 출력해서 확인:
   - **이순신고**: 1-1, 1-2가 각각 3.5학점이어야 함
   - **천안 지역 학교 한 곳**: 1학년과 3학년 학점이 다른지 확인
   - **천안중앙고 또는 임의의 일반 학교**: 정상 학점
2. 합계가 16~24학점 범위인지 (학교마다 다르지만 상식 범위) 검증.
3. JSON 구조 검증: 모든 학교의 `changche.semesters` 길이가 6인지.

검증 통과 시 WORK_LOG.md에 기록 후 A-3으로.
검증 실패 시 사용자에게 보고하고 멈춘다.

## A-4. ★ 중복 이수 방지 (계열 추천 핵심 버그)

목적: 충남외고 중국어과 + 인문어문 추천 시 "문학"이 4학기 연속 선택되는 버그 해결.

수행할 작업:

1. `index.html`의 `applyPreset()` 함수 분석. 현재 알고리즘은:
   ```
   for each group:
     for each active semester:
       각 학기마다 우선순위 높은 K개 골라서 선택
   ```
   문제: 같은 과목이 모든 학기에 선택됨.

2. 다음 알고리즘으로 교체:
   ```
   for each group:
     pickedSubjects = new Set()  // 이 그룹에서 이미 선택된 과목 si
     for each active semester (순서대로):
       candidates = subjects sorted by preset score desc
                    .filter(s => !pickedSubjects.has(s.si))
       take top K from candidates
       picked.forEach(s => pickedSubjects.add(s.si))
       selectedCells.add(`g{gi}-s{s.si}-sem{semIdx}`)
   ```

3. 엣지 케이스 처리:
   - **후보 부족**: 점수 매칭된 과목이 K보다 적으면 점수 -1인 과목도 채워야 함.
     이 경우에도 같은 과목 중복 금지 규칙 유지.
   - **그룹 전체 과목 수가 active_sem * K보다 적은 경우**: 가능한 만큼만 채우고
     `console.warn`으로 알림. 학생에게는 그룹 충족 배지가 ✗로 자동 표시되므로
     별도 알림은 불필요.
   - **추천 점수 동점**: 안정 정렬 보장 (subjects 배열 순서대로).

4. 변경 전후 비교 확인용으로 다음 함수 추가 (디버그용, 콘솔에만):
   ```js
   function debugPresetSelection(presetKey) {
     // 현재 상태에서 추천 적용 후 그룹별 선택 결과 출력
   }
   ```
   배포 직전 제거할 것.

검증 단계:

1. 로컬 서버로 띄워서 다음 시나리오 모두 통과:
   - **충남외고 중국어과 + 인문·어문**: 선택 1 그룹에서 같은 과목이 두 학기 이상
     선택된 게 **없어야 함**.
   - **천안중앙고 + 이공·자연**: 미적분Ⅰ과 미적분Ⅱ가 각각 다른 학기에 정확히
     **한 번씩** 들어가야 함.
   - **모든 선택 그룹의 충족 배지**: ✓ 충족 또는 (후보 부족 시) 부족분 명시.

2. 각 시나리오를 콘솔에서 `debugPresetSelection('humanities')` 등으로 검증.

3. 디버그 함수 제거.

⏸ **사용자 확인 필요**: 위 시나리오 결과 보고 후 OK 받으면 A-5로.

## A-6. 과학(군) / 정보과학 분리

목적: 정보과학 과목이 자연과학과 같은 카테고리로 표시되는 문제 해결.

수행할 작업:

1. 일회용 분석 스크립트 작성:
   - `courseDB.json`과 모든 편제 JSON을 순회.
   - `교과군` 필드 값의 실제 분포 출력 (어떤 값이 몇 개 과목에 사용되는지).
   - "과학" 카테고리 안의 과목명 예시 출력 (자연과학·정보과학이 섞여 있는지 확인).

⏸ **사용자 확인 필요**: 분석 결과 보고. 다음 중 하나로 결정:
- (a) 데이터에 이미 정보과학이 별도 카테고리로 있음 → UI에서만 분리 표시 처리
- (b) 데이터가 섞여 있음 → 분리 매핑 규칙 확정 후 `extract_data.py`에서 정규화

2. 결정에 따라 처리:

   **(a) UI만 수정 시**: `index.html`의 `updateCounter()`에서 정렬 우선순위·표시명
   조정. 기존 ord 배열에 '정보과학' 위치 명확히.

   **(b) 데이터 정규화 시**:
   - `extract_data.py`에 정규화 단계 추가:
     ```python
     SCIENCE_INFO_KEYWORDS = ['정보과학', '인공지능', '데이터과학', '소프트웨어', ...]
     def normalize_group(group, subject_name):
         if group == '과학' and any(k in subject_name for k in SCIENCE_INFO_KEYWORDS):
             return '정보과학'
         return group
     ```
   - 편제 JSON과 courseDB.json 양쪽에 적용.
   - 재추출 실행.

3. UI 라벨 정리: 우측 패널 교과군별 표시에서 "과학(자연)" vs "정보과학"으로
   구분되어 보이도록.

검증 단계:

1. 북일고 + 이공·자연 추천 적용.
2. 우측 패널 교과군별에서 자연과학과 정보과학이 분리되어 표시되는지.
3. 다른 학교들도 의도치 않은 카테고리 변경 없는지 1~2곳 샘플 확인.

⏸ **사용자 확인 필요**: 결과 보고 후 OK 받으면 A-7로.

## A-7. 평가 처리 유형 표시

수행할 작업:

1. `extract_data.py`에 평가유형 시트(A-1에서 확정) 추출 로직 추가:

4. `index.html` 수정:
   - `renderGroup()`의 과목 행에서 과목명 옆 또는 학점 셀 옆에 `evaluation` 배지 추가.
   - 배지 스타일: 기존 `type-badge`와 비슷한 작은 pill, 색상은 회색 계열로 차분하게.
   - `evaluation`이 빈 값이면 배지 생략.

검증 단계:

1. 천안중앙고 선택해서 과목 옆에 평가유형 배지 표시 확인.

3. 평가유형 데이터 없는 과목(예: 창체)에 빈 배지 안 뜨는지.

⏸ **사용자 확인 필요**: 결과 보고 후 OK 받으면 A-8로.
